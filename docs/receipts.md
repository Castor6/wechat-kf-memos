# 最终结果回执（0.1.2）

配置 `RECEIPTS_ENABLED=true` 开启，通用示例默认关闭，当前个人部署已开启。只对配置白名单中的发送者回复。

## 对外表现

- 无“收到/正在处理”提示。
- 全部可获取内容保存完成后：`文字保存成功`、`图片保存成功`、`聊天记录保存成功` 等。无标题、标签、空间或链接。
- 图片/语音/视频/文件仍各自创建一篇笔记，并关联附件，不是只进附件库。
- 未成功的操作最多自动尝试 12 次，期间不重复打扰。最终提示实际环节、脱敏原因和尝试次数，例如 `文件保存失败：Memos 创建笔记：认证失败，HTTP 401，已尝试 12 次`。
- 已创建笔记但附件或最终正文未完成，明确提示“部分保存：笔记已创建，后续处理失败”，不宣称完整成功。
- 独立 `note` 消息：`微信笔记保存失败：微信接口未提供笔记内容`。不创建占位笔记，不做无意义重试。
- 聊天记录中夹带微信笔记、缺失附件 ID、无法解析条目等，保留其他可获取内容并回复“聊天记录部分保存”及原因。
- 纯文本 URL 按文字；实际 `link` 消息按链接；`merged_msg` 对外统一叫聊天记录。

## 可靠性

剪藏完成/最终失败与回复入队在同一 SQLite 事务提交；回复只负责发消息，不再创建或更新 Memos。来源消息去重，最终回复使用固定且不超过 32 字节的微信 msgid，同一任务不会因重复拉取而新增回复。

发送前持久化 sending 状态。若请求响应丢失或发送中进程中断，无法证明微信是否收到，因此标记 unknown，不盲目再次发送。不能声称网络故障下绝对保证恰好投递一次。明确的 API 拒绝或连接建立失败在剩余额度内退避；微信异步 msg_send_fail 事件将对应回复标为 delivery_failed。状态命令显示回复各状态计数，详细错误保留在回复表。

正常处理一条消息只发一次最终结果。不补发升级之前所有历史消息。本次上线为已保存的最新聊天记录单独排入一条验证回执，未重新剪藏。

## 微信限制

依据 [独立客服发送接口](https://kf.weixin.qq.com/api/doc/path/94744)：用户主动发送后 48 小时内最多回复 5 条，继续发送后可以再次下发。不将多个输入当作可累加的无限额度。维护最近输入窗口，单窗口最多发起 5 次发送；新输入才重置计数，重复拉取不重置。连续大量发送时，待发结果可能等到下次输入或过期；过期状态保留，不无限补发。

回复失败不回滚已保存笔记。微信接口成功仅证明接口接受请求，不替代手机端可见性验证；未知或发送失败记录可供开发者排查。任何错误消息都不拼接远端响应正文、含令牌 URL 或配置密钥。

## 验证

51 项测试通过（含两种标签模式的本机真实 Memos API 测试）。新增测试覆盖独立微信笔记零笔记、只有最终回执、重复拉取/执行、失败 12 次后提示、附件具体原因、断线和重启防重复发送、5 次限制/过期、新输入恢复额度、异步发送失败事件和白名单。

2026-09-19 已部署 0.1.2；真实微信接口接受“聊天记录保存成功”，回执 sent、attempts=1、error=null，原有完成任务仍为 2 条，没有新增重复笔记。端到端失败情况及微信笔记分支使用自动化测试验证，尚未诱发生产故障或用真实微信笔记样本验证。

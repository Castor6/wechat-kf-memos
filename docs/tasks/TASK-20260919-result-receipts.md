# TASK-20260919-result-receipts：最终结果回执与微信笔记处理

- 记录日期：2026-09-19（按既有证据整理的历史事实）
- 模块与关键词：回执、失败原因、微信笔记、额度、0.1.2
- 来源：本项目既有模块文档、开发验证记录及本次项目讨论

## 背景与目标

用户只需要保存结果，且失败应说明开发者可排查的具体原因。成功回复在“保存成功”前标明实际处理类型。

## 验收标准与事实

- [x] 不发“收到”或“处理中”；完整成功只回“类型保存成功”，不含笔记链接、标题、标签、空间。
- [x] 最终失败说明环节、脱敏原因/代码和尝试次数，不统一要求稍后重发；部分保存明确说明。
- [x] 独立微信笔记因官方未提供正文，不创建占位 Memos；聊天内不可获取内容报告部分保存。
- [x] 回执独立持久化，重复拉取不重复剪藏或排入回复；发送不确定时不盲目重发。

## 讨论结论

图片、语音、视频和文件各自仍是一篇笔记及所属附件。文字 URL 按文字，实际链接卡片按链接，对外统一称“聊天记录”。回复窗口依据用户主动输入，不能解释成整个客服号每两天总共只有五条，也不能把输入无限累加成额度。

## 验证事实与边界

2026-09-19 完成并部署 0.1.2；51 项测试与 Ruff 通过，含两项临时真实 Memos API 测试。覆盖最后结果、12 次失败重试、具体错误、微信笔记零写入、断线/重启、额度/过期、异步发送失败及白名单。

该次生产验证只给最近已保存聊天记录补发一条结果，官方接口接受“聊天记录保存成功”，没有重新创建笔记。不批量补发历史记录。API 接受不等于手机端已读；该次未使用真实微信笔记样本或诱发生产故障。整理本记录时未重跑测试、未操作生产。

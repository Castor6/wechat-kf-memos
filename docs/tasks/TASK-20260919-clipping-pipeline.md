# TASK-20260919-clipping-pipeline：剪藏流水线、消息与附件

- 记录日期：2026-09-19（按既有证据整理的历史事实）
- 模块与关键词：剪藏、SQLite、白名单、聊天记录、附件
- 来源：本项目既有模块文档、开发验证记录及本次项目讨论

## 背景与目标

把“剪藏”作为入口：本人发送或转发一条内容，保存为一篇私有 Memos。原先独立 MD 文件方案改成 Memos Markdown 正文及附件，便于回顾和后续 AI 使用。

## 验收标准与事实

- [x] 官方通知先持久化，后台拉取消息；游标和任务同事务提交，白名单、固定 ID、重试及重启恢复保留。
- [x] 文字和聊天记录创建笔记；图片、语音、视频、文件创建笔记并关联附件。聊天媒体放入同篇笔记。
- [x] 单进程运行；SQLite 保存队列、游标和去重状态，成功任务清除原消息正文。失败数据仍按敏感资料保护。
- [x] 媒体在内存暂存，长期只由 Memos 保管；不直接修改 Memos 数据库。

## 讨论结论

默认每篇带“微信剪藏”，聊天记录额外带“微信聊天记录”。直接文字的 #tag 用于分类，历史聊天的井号保留原文。文章不抓全文，语音不转写，图片不 OCR。独立微信笔记的最终规则见[回执任务](TASK-20260919-result-receipts.md)。

## 验证事实与边界

初版 37 项单元/模拟测试与 1 项本机临时真实 Memos 测试通过。2026-09-19 建立本人白名单并启用正式剪藏；首条真实文字及后续聊天记录保存成功。曾实际检查 PRIVATE、正文和标签，没有直接读写生产数据库。

本次历史验收未逐项覆盖真实图片、语音、视频、文件及各种卡片；不能把模拟消息矩阵视为全部真机验收。长正文尚无自动拆分，素材过期可能无法补回，当前无附件落盘缓存。本记录整理时未重跑应用测试。

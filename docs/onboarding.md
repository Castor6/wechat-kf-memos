# 微信客服开通与接入

记录日期：2026-09-19。下面整理本次成功路径；后台名称、资格和额度可能变化，重新开通时以自己的官方后台为准。

## 账号路径

1. 从[微信客服独立后台](https://kf.weixin.qq.com/)注册，填写组织信息，由本人微信扫码完成管理员验证。本次使用未认证账号，未办理付费认证或提交营业执照。不是公众号，也不是企业微信自建应用；不选不能登录管理后台的简化团队形态。
2. 注册后仍会获得平台分配的“企业 ID”（CorpID）。未认证不等于没有企业 ID；无需自己另造一个。后台当时显示累计接待 100 位客户，按客户人数而非消息数计算。
3. 确认已有客服账号，记录其 `open_kfid`。`kf` 是客服接口命名；客服账号 ID、企业 ID、客户 `external_userid` 是不同标识。
4. 从独立后台开发配置取得客服 Secret。不要取企业微信自建应用 Secret。账号与额度背景见[官方使用说明](https://open.work.weixin.qq.com/help2/pc/17961)；接口入口见[官方接口依据](official-api.md)。

## 先验证回调

1. 本机运行 `uv run python -m wechat_kf_memos init-env`，生成权限 600 的配置，填入企业 ID。工具不输出密钥。后台 Token 为 3–32 位字母数字；本次独立后台要求 EncodingAESKey 为 43 位字母数字，工具生成符合要求的有效 AES 密钥。
2. 部署服务 `MODE=verify`，用 Nginx 转发 HTTPS 精确路径 `/wechat/callback`；服务只监听环回地址。
3. 后台填 URL、Token、EncodingAESKey 并保存。服务验证签名、解密 echostr 并原样返回。
4. 本次只有公网 IP、没有域名，实际 HTTPS 回调成功；HTTP 80 验证未通过。沿用已有证书，没有重签。这个结果仅证明本次环境，不能保证任意证书或 IP 均被接受。
5. verify 只处理地址验证，消息通知返回 503。若暂不继续联调，应停用后台 API，不要长期开着仅验证服务。最初探针验证后曾撤除；随后部署正式服务重新启用。

## 正式剪藏

1. 在私有配置中填写 CorpID、客服 Secret、open_kfid；调用客服列表核对账号。所有密钥直接写入受保护配置，不输出到聊天或截图。
2. 在定制 Memos 创建专用访问令牌，配置 MEMOS_URL/MEMOS_TOKEN。开启 `MEMOS_TAG_MODE=explicit`、`RECEIPTS_ENABLED=true`。
3. 自己发送一条随机、无隐私的识别文字，用 `discover-users` 查看候选客户标识，并核对确属自己的那条消息。只将本人标识加入 WECHAT_ALLOWED_USERS，不能自动授权首位访客。
4. 设置 `MODE=clip`，以单进程 systemd 服务运行并启用自启。环境文件、SQLite 状态、备份均留在私有路径，参见 README 的存储与恢复说明。
5. 发文字及标签，再转发聊天记录；核对 Memos 为 PRIVATE、默认个人空间、独立标签、正文纯净、顺序正确、没有重复。随后逐项验证真实媒体。
6. 保存完成只发“类型保存成功”；失败给出脱敏具体原因，不先发“收到”。接口接受不代表手机端已读。

本次已走通真实文字和聊天记录及一次最终回执。真实二进制媒体与各类卡片仍待逐项验收。客户信息导出、数据库和真实聊天样本不得上传仓库。修改生产配置前备份；凭据一旦进入输出或公开文件，先撤销/轮换再继续。
